I want to create a Session Management Tool, which will be reused for all of my projects.

The goal is to create Session Handling mechanisms so the implementation sessions are monitoring token usage and availability.
The agents should acknowledge when they're going to run out of tokens soon, and when that happens, will do the following:
* Update agents/session_handling.md
* Update agents/tasks.md

An agent should NEVER run out of tokens before ensuring the session will be gracefully handled to the next agent. The next agents should always know what to do based on the instructions left by the previous agent.

I will have a cron job that will trigger the next agentic run in X hours (when the session limit is reset).

The projects will be organized the following way:

* agents/description.txt file (like this one) explaining WHAT I want to build and it's requirements. This file will be used to generate the plan. Will remain unused for the rest of the runs.
* agents/plan.md this file will contain the output of the plan created by Claude (on the planning step). This will be unaltered forever once it's created.
* agents/session_handling.md file will contain a summary on what's been done the last session and what need's to be done to continue the implementation.
* agents/tasks.md this file will include the checkmark list (updated always) 
* agents/session_management_instructions.md this file will contain instructions on how to be compliant with this framework. will be referenced by description on the first run.
* agents/architecture.md including descriptions on design patterns and architecture and general engineering decisions.
* CLAUDE.md will instruct for new runs on how to interact with the whole agents/ documentation folder.

When starting to work on new sessions / tasks, the agent should first review the state of the repo, then what's needed, and then implement, always ending with the update status of the agents/ files.

Also, before starting the implementation, asks any questions needed and identify performance gaps.

Everything should be concisely explained (to save tokens) but also to the level of detail that promises maximum efficiency.
